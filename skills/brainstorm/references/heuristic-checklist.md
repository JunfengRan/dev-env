# Brainstorm 启发式自检

## 过程

- [ ] 已征得用户同意，或用户主动要求 brainstorm
- [ ] 未在用户明确拒绝后继续长篇澄清
- [ ] 澄清阶段基本一次一问
- [ ] 给出 2–3 方案且有明确推荐
- [ ] 大范围请求已先拆分（若适用）

## 内容

- [ ] 目的 / 约束 / 成功标准说清
- [ ] 非目标或 YAGNI 裁剪说清
- [ ] 实现断言标「待验证」或附证据路径
- [ ] 跟随现有代码模式，无无关重构

## 落盘（可选）

- [ ] 路径在 `docs/design/` 或 research brief 草稿中
- [ ] 无 TBD / 内部矛盾 / 未拍板歧义
- [ ] 交接下一 skill 已说明，未伪造 Spec state 推进

## 红线

- 把 brainstorm 写成 Spec 必经 phase
- 未同意就开问卷式连环问
- 用 brainstorm 替代源码取证（研究问题应交 deep-research verify）
